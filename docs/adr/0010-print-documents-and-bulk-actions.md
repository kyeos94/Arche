# ADR 0010 — 양식 인쇄와 계약 목록 일괄 작업

## 상황
변제 독촉장·기한이익상실 통보서를 계약 1건 또는 계약 목록에서 여러 건 인쇄해야 한다. 양식은 치환 문자열 방식이고,
계약 목록의 일괄 작업은 앞으로 문자 일괄 발송, 담당자·속성 일괄 변경으로 늘어난다.

## 결정
1. **양식은 DB의 HTML + CSS, 치환은 서버.** `print_template`에 양식 원본을 두고 `{{고객명}}` 같은 치환 문자열을
   `document` 모듈이 계약 값으로 채워 HTML 조각을 돌려준다. 값은 서버가 HTML 이스케이프한다. 화면에서 치환하면
   주소·금액 원문을 화면 API로 내려야 하고, 접근 기록·대상 판정을 화면이 우회할 수 있어서 서버에서 한다.
2. **치환 문자열 목록은 코드(`DocumentPlaceholders`)가 정한다.** 모르는 이름은 양식 저장 시 거절, 값이 없으면 '-'.
   식별번호는 목록에 넣지 않는다. 기본 양식이 목록 밖 이름을 쓰지 않는지 단위 테스트가 마이그레이션 파일을 검사한다.
3. **인쇄는 브라우저 인쇄.** PDF 라이브러리를 들이지 않고, 숨긴 iframe에 A4 문서를 쓰고 `print()`를 부른다
   (페이지 나눔은 CSS). 미리보기도 iframe `srcdoc`이라 양식 CSS가 업무 화면에 새지 않는다.
4. **미리보기와 인쇄를 나눈다.** 인쇄만 문서번호(`P{업무일자}-{배치}-{순번}`)를 매기고 이력을 남긴다.
5. **일괄 처리는 건너뛰기 방식.** 대상이 아니거나 볼 수 없는 계약이 섞여 있어도 나머지는 처리하고 건너뛴 이유를 보여 준다.
6. **계약 목록 일괄 작업은 등록식.** 화면의 `bulkActions` 배열에 `{ key, label, 권한, 대화상자 컴포넌트 }`를 추가하면
   선택한 계약으로 그 작업을 띄운다. 선택은 페이지를 넘겨도 유지하고, 검색 조건이 바뀌면 비운다. 서버는 작업마다
   계약 id 목록을 받는 API를 두고(권한·데이터 범위·건너뛰기 규칙은 작업마다 다르므로) 공통 일괄 API는 두지 않는다.

## 결과
- 새 양식은 마이그레이션(또는 이후 양식 관리 화면)으로 행을 넣으면 되고, 대상 규칙(`target_rule`)이 새로 필요할 때만 코드를 고친다.
- 일괄 문자 발송·담당자 변경은 `bulkActions`에 항목 하나와 서버 API 하나를 더하는 일이다 (README 확장 지점).
