# ADR 0011: 목록 정렬·계약 목록 상세 검색·페이징·문자 일괄 발송

- 상태: 채택
- 날짜: 2026-11-01

## 배경

사용자 요청(2026-11-01):
1. 계약 목록에서 선택한 계약에 문자를 한 번에 보내기 (계약 상세 우측 타임라인의 문자 발송을 여러 건에)
2. 계약 목록의 모든 표시 항목으로 검색 (상품, 상태, 금액 범위, 담당자, 계약번호·성명·주민번호 등)
3. 한 페이지 N건 + 페이지 이동
4. 모든 메뉴의 표 머리글을 눌러 오름차순·내림차순 정렬

## 결정

### 정렬 (모든 표)
- 공통 부품 `lib/useSort.ts`(브라우저 정렬 훅)와 `SortTH`(머리글). 누를 때마다 오름차순 → 내림차순 → 해제.
- 숫자는 숫자 순, 글자는 `Intl.Collator('ko', { numeric: true })`(한글 순서 + L9 < L10 자연 정렬), 빈 값은 방향과 관계없이 뒤로.
- 이미 화면에 다 받은 표는 브라우저에서 정렬한다(추가 요청 없음). 페이지로 나눠 받는 계약 목록은 서버가 정렬하고 같은 `SortTH`를 쓴다.
- 정렬할 수 없는 칸(체크박스·버튼·여러 값을 묶은 칸)은 일반 `TH`로 둔다.

### 계약 목록 검색·페이징
- 검색 조건은 servicing 공개 API `LoanFilter` 하나로 정의하고 목록 API와 엑셀 다운로드(R68)가 같은 SQL 조건을 쓴다(화면과 파일 결과가 같도록).
- 동적 조건은 JdbcClient + 이름 붙은 파라미터로 조립한다. 정렬 칸은 허용 목록으로만 받는다(SQL 주입 방지). QueryDSL은 쓰지 않는다(ADR 0001).
- 고객 조건(성명 부분 일치, 주민등록번호·휴대폰 블라인드 인덱스 일치)은 customer 모듈 공개 API로 고객 ID를 얻어 넘긴다. 주민등록번호·휴대폰 검색은 접근 기록에 남기고 입력값은 남기지 않는다.
- 페이지 크기는 20·50·100·200 중에서 고르고 URL 쿼리스트링에 남긴다(뒤로 가기·링크 공유).

### 문자 일괄 발송
- 계약 상세 문자 발송과 같은 서비스(`CommunicationService.send`)를 계약마다 따로 부른다. 7일 7회·연락 유예·추심 중지·야간 예약 규칙이 계약마다 그대로 적용되고, 한 계약이 실패해도 나머지는 보낸다.
- 결과는 계약별 발송·예약·차단·제외(이유)로 돌려준다. 한 번에 200건까지.
- 일괄 작업 등록표(ADR 0010)에 항목 하나로 붙인다.
